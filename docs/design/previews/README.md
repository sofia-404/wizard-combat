Game captures use desktop 1920x1080 and narrow 390x844 viewports. Brandbook captures use a 1920x1080 viewport. Image height follows the full page or cropped element. All captures use Chromium, device scale factor 1, reduced motion, and loaded fonts. Browser versions can change pixel output.

The browser test blocks `getUserMedia` and checks that no camera call occurs. Game settings are Drawing hand Left and Track point Index fingertip. Options uses separate Music volume and Sound effects volume sliders. Practice Arena and Spell Training show Start camera in the arena center. Idle motion is disabled for these captures. Lesson setup briefly simulates camera readiness to start the lesson automatically without a stream. The camera has no stream in saved previews. Some combat states show simulated readiness and a Stop camera button. Mode navigation updates the camera status. Spell guide crops have no live input.

## Capture and review

From the project root, run:

```sh
npm run test:input
```

The existing Playwright setup is required. Set `CHROMIUM_EXECUTABLE` to use an installed Chromium executable. The capture code is in `tests/browser-input-settings.mjs`.

```text
Capture to .tmp/input-settings/ -> Inspect -> Copy selected files here
```

1. Require a passing test run. The command only writes candidates to `.tmp/input-settings/`; it does not replace these references.
2. Inspect both sizes. Check fonts, artwork, text, guide arrows, and start/stop marks. Full pages must include the lesson controls and event panels, with no repeated sections or clipping. Brandbook crops must include the concept label.
3. Copy only the reviewed files listed in the table. Use the same names. Keep Options and other test-only captures in `.tmp/`.
4. When visible copy or layout changes, refresh the affected set. When a shared guide style changes, refresh all four guide pairs. When a spell guide changes, refresh its pair and the Spell Training layout pair if it shows that spell.
5. Check image links and the final diff. Update this table when the saved scope or capture state changes.

The browser check tests input settings and layout overflow. Image review is manual; it does not compare saved PNG files.

Solo Duel combat previews use `npm run test:solo-duel`. The test blocks real camera access and simulates readiness without a stream. Stop camera is visible only because of that simulated state. Review the desktop and narrow candidates in `.tmp/solo-combat/`, then copy only the Solo Duel files listed above. These images are not physical player tests.

Protego training combat previews use `npm run test:protego-training`. The test blocks camera access and uses a controlled clock. Review both widths in `.tmp/protego-training/`, then copy only the warning, block, and complete pairs listed above. These captures are simulated input, not physical player tests.

Stage selection previews use `npm run test:navigation`. Review `.tmp/stage-selection/stage-selection-1920.png` and `stage-selection-390.png`, then copy them to the desktop and mobile stage-selection names above. The same test checks all nine backgrounds in all three modes, reload, history, random selection, and failed or cancelled image loads.

For the selected-stage pair, open `?mode=soloDuel&character=original-wizard#stages`, click Slytherin Dungeon once, move the pointer away, and capture the full page at both standard widths after fonts and images load. Keep camera access blocked. Review the candidates in `.tmp/` before copying them here.

For the hover pair, use the same route and widths with a mouse. Hover over Slytherin Dungeon without clicking. Keep the initial courtyard preview and no selected tile. Capture after fonts and images load, then review before saving.

Character selection previews use `npm run test:navigation`. Review the player, opponent, practice, and stage candidates in `.tmp/character-selection/`, then copy the pairs listed above. The same test checks all portraits, Random, image retry and cancellation, keyboard navigation, stage handoff, reload, history, and Restart with the real camera blocked. Battle skins are checked by `tests/browser-battle-skins.mjs` in the same navigation command. Review the candidates in `.tmp/battle-skins/` before copying the three skin preview pairs. The check covers all 11 skins for both roles, same-stage skin changes, reload, Restart, image retry, the unchanged practice dummies, wand-drop position, spell origin, and simulated game events. It blocks real camera access.

Shared round previews use `npm run test:rounds`. The test blocks real camera access and uses a controlled clock. Review `.tmp/rounds/` at both standard sizes. The `practiceArena-*` and `soloDuel-*` candidates map to the hyphenated round preview names above. The same run supplies the Practice Arena gameplay, match result, and player defeat pairs. Use these round-aware captures for those three pairs. Solo Duel combat-state pairs still come from `npm run test:solo-duel`. Stop camera in a round preview means simulated readiness, not an active camera stream.
